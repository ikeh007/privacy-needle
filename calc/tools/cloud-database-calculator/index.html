How this estimate works

Cloudflare D1 documents a Workers Free allowance of five million rows read daily, 100,000 rows written daily, five gigabytes of combined storage and ten databases. Hitting a free-plan usage limit can stop queries or writes until limits reset or the plan changes. These are not soft thresholds that simply begin billing.

For paid D1 usage, the estimator separately accounts for excess paid-tier row allowances and storage; it leaves Workers/hosting base pricing as an explicit editable assumption. The stored amount includes an assumed percentage for indexes. Actual read counts come from query metrics, not from the number of web requests.

For PostgreSQL/MySQL, change to custom mode and enter the prices from the actual hosting provider. A self-hosted engine does not automatically have a free tier; replicas, storage, backup, network egress and support can each add cost.

Growth note: The month-to-limit estimate only compounds storage at the selected growth rate; it does not predict real traffic, compression or lifecycle policy effects.

Frequently asked questions

When will my Cloudflare D1 database exceed the free plan?

Check daily rows read against 5 million, rows written against 100,000, total account storage against 5GB and database count against 10. These are free-plan constraints, not invoices.

Does one SQL SELECT equal one D1 read row?

No. D1 meters rows read or scanned by the query, which can be greater than the number of rows returned. Indexes matter.

Can you calculate a universal PostgreSQL or MySQL free tier?

No. PostgreSQL and MySQL are database engines. Free plans depend on the managed host, compute choices, included storage and region.

Does adding shards always reduce cost?

No. Shards and replicas add compute and operational overhead. Actual performance and metered usage depend on data distribution, replication and query design.
